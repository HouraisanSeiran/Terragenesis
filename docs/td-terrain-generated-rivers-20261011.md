# 原始 TD 地形上的全域河网与实际河床生成

状态：第四批固定六源生成与定向修复、主协调独立全六冷读及最终图像审查完成。贴近现实的最终形态目标尚未完成。

本轮接通原始 Terrain Diffusion 地形、噪波降雨、汇水路由、河网选取、实际河床与保存结果审核。输入为原有固定生成清单中的全部六份 513×513、30m 原始高程，按清单顺序处理；没有手绘河道、下采样后生成或按输出挑选样本。算法调试已经使用这些样本，因此不再称它们为新算法的独立留出集。

## 实现与参数

- `metric_td_generated_source.py` 校验原始 NPZ、生成报告、计划、种子、原点与模型配置身份；保持原始 float32 数值，转换为 float64 运算。
- `metric_td_generated_rivers.py` 使用原床 D8 作为对照，再调用固定 `pyflwdir==0.5.12` 的有界洼地处理生成工作路由。工作面与原床分开保存，工作面填高不计入实际开挖量，也不解释成湖水。
- 噪波降雨场派生局地产流并沿全图汇总。当前 Q 是 0–900 秒平均降雨对应的诊断分配，没有水流传播时间、水面或蓄水演算。
- 对全部选定边按完整连通组件构造连续床面包络，在汇流节点共享床高；源头、汇流点和终点保持锚定，其他中心线节点在原地形约束内平滑。
- 河槽以 1m 稀疏三角网格表示，用实际三角平面沿流向的梯度约束床坡。常规生成的新组件保留连续设计底宽、河深和中心床面，以必要切深下界求解最小开挖体积；保守支撑扩大只在已知域内，内部河岸接缝切深为零。第四批混合旧组件时锁定旧实际床面，并明确新设计证明的适用区域。
- 材料账积分最终唯一网格，分开记录组件重叠体积、必要下界、闭合增量和相对原组件包络的净变化，不把侧向开挖回升误计为重叠扣除。
- 有限域的边缘断面沿原法线截到已知边界，分别保存请求与实际宽度。裁切断面标为不完整，域外保持未知。

| 项目 | 当前设定 |
| --- | --- |
| 选河汇水面积阈值 | 1km² |
| 产流系数 | 0.5，场景参数 |
| 工作填洼深度上限 | 4m，保留更深洼地终端 |
| 实际最大切深 | 4m |
| 实际最小床坡 | 1e-5 m/m，数值审核容差 1e-8 m/m |
| 河宽/初始河深 | 随诊断 Q 变化的工程关系，尚未现实标定 |
| 中心线移动 | 最多 8 轮，距原节点不超过 6m，原床升高不超过 0.5m |
| 域外及自然海口 | 未知，未认证 |

原始节点跨度 15360m；汇水离散按 513 个 30m 方形单元计面积，单元足迹为 15390m。两者是明确的不同几何约定。全部来源缺少已知外部延续、完整湖泊边界与实测垂直基准。

## 实跑修复过程

第一轮 `verification/td-terrain-generated-rivers/generated-20261011-01/` 完成全部六源并冷读，但仅 11254/27336 条选定边形成实际河床。该覆盖率不能作为全域生成完成的证明。原床对照的首源最长候选路径约 729m；有界洼地路由使候选路径延长至 11294m。

进一步诊断发现，旧线性节点深度传播比真实连续床包络更严格。例如来源 2 的 1370 边组件旧公式要求约 7.82m 下切，新连续包络保持原路径可以在约 3.43m 节点切深下成立。域外断面被误当作整个组件不可生成的问题也得到修复。真实超过当前切深预算的组件仍拒绝。

第二轮 `generated-20261011-02` 因实际床坡门槛失败而中止，partial、日志和失败说明保留。绝对高差求解容差在极短河段上不能保证物理坡度；修复后直接约束三角床面方向梯度，独立审核自行求解三角平面的梯度，不复用生成器求解矩阵。

修复后的同一 1370 边组件通过主协调独立冷读：最大实际切深 3.62431m，最低床坡约 9.9999871e-6 m/m（在声明数值误差内），没有反坡，934 个节点实际移动。实际河槽最长连续路径约 13.731km，精确沿八个栅格方向的河段约占 22.12%。这是组件修复证据，不能替代最终六源结果。

主协调独立运行 28 项相关测试通过，覆盖来源、生成、既有单调床面、稀疏/分块网格和独立审核。真实数据的失败也已用于修复，不以单元测试代替全域实际验收。

最终修复接入后，主协调完成 38 项相关回归；审核新增设计深度统计测试后，受影响的 11 项审核测试再次通过，最终有效测试集合共 39 项。一次测试调用误写分块测试模块名，已更正为 `tests.test_metric_valley_tiled_union` 并单独运行其 4 项测试通过，没有将未加载测试算作通过。

第三轮实际运行又发现两类具体问题。来源 0 的一个组件因大世界坐标下约 6.4e-10m 的三角支撑误差被拒绝；来源 1 的 3160 边组件因相邻弯道的侧向最大开挖包络过约束而无解。固定网格诊断中，锁定旧包络需要 4.17623m，而仅取消包络虽然可解，却不能保证设计断面。第一次设计下界试算在实际底宽内发现最多约 0.11023m 欠深，因此未作为有效修复交付。

进一步试算保留设计宽深、连续中心床高和真实三角坡度，并补足原始双线性 TD 与三角源面之间的插值误差，4m 内可解，最小必要最大切深约 3.99323m。此项记录位于 `component-budget-diagnosis-20261011-02/continuous-certificate-counterfactual-02/report.json`，仍为固定网格诊断；正式接入还须处理河岸支撑与原地形回接，并冷读最终组件和全局床面。主协调另独立运行新增设计床面模块的 3 项测试通过；这不替代上述实际生成验收。

随后在扩大河岸支撑的实际组件上完成求解和独立冷读，来源 1 的 3160 条河段全部保留。产物含 7135008 个三角面，唯一开挖体积 324948.58544m³，最低实际物理坡度约 9.99999994e-6m/m，连续原始 TD 切深上限 4m。299858 个内部支撑边界顶点全部零切削；26 个域边界顶点保持域外未知。设计底宽内连续深度的最小余量为约 -2.85e-14m，处于浮点误差内。完整证据位于 `component-budget-diagnosis-20261011-02/actual-expanded-design-counterfactual-01/`；finalized 仅补齐加载元数据，已断言全部河床数组不变，并通过标准冷加载与独立审核。该文件可作为明确记录来源的组件复用，仍需验证最终全局合并结果。

## 现实感与能力边界

主协调已查看最终固定局部图，数值通过仍伴随明确的形态问题：来源 1 保留明显的 45/90 度栅格折角，宽支撑区域中存在很细的深切中心槽；其断面是浅设计底部叠加狭窄深槽，不能解释为自然宽河床。来源 2 弯线较顺，但河槽依旧窄且规则，固定横断面中的河道并非整个 300m 窗口最低处。来源 3 沿谷底生成，但长斜直段与折角明显。这些是最终保存几何的实际表现，未通过换取样点或展示平滑消除。

新的连续设计约束解决了底宽范围内欠深与过约束无解，但最小体积目标仍允许把额外纵向下切集中到中心窄槽。彩色三角支撑的宽度也不等于实际深槽底宽。因此本轮完成的是全六源生成、修复和审查交付，尚未完成“贴近现实河流”的最终目标。下一步应优先处理真实断面的深切分布与岸坡、地形约束下的栅格折角，再处理超预算洼地的湖泊/溢流及匹配尺度的现实参考验证。

当前产物是地形驱动的实际河网/河床候选。工作填洼平区仍可能产生明显直线；河宽/深度关系、最低坡度和 4m 切深属于工程设定。更深洼地仅保留为内部终端，尚没有由同源水量平衡确定的完整湖面和溢流过程。还没有求解全域河道水面或泥沙演化，也没有匹配新生成尺度的现实河网分布验收。旧 90m、48×48、10万m² 阈值的参考不能直接认证本轮 30m、513×513、100万m² 结果。

最终自然可信目标与可发布状态仍须依据这些缺口的实际完成情况判断，不能从保存产物审核通过推导。

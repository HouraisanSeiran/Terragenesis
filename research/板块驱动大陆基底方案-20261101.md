# 板块驱动大陆基底方案

日期：2026-11-01。状态：研究与接入设计，未实现算法、未修改 UI、未运行板块模拟或 TD 推理。固定世界种子沿用 `20261020`。本轮暂停 500 km 综合验收；本文不将既有验收图改称板块生成结果。

## 结论与范围

建议采用“显式大陆壳初态 + Voronoi 初始板块 + 简化时间演化 + 冻结宏观底图 + TD 条件适配”。Voronoi 负责初始板块分区；大陆壳不是整个 Voronoi 多边形，海岸线由随板块迁移、碰撞和裂解后的壳状态及海平面导出。宏观预览必须直接采样这份冻结底图。

只根据板块边界的相向速度绘制山脉、再叠加噪波海陆，属于构造边界启发式，不能满足“大陆由板块构造生成”的完整意图。建议第一版至少保留随时间迁移的大陆壳、相撞增厚/拼合、海壳俯冲、张裂补充海壳和初末态记录；可以使用规定速度，不要求求解地幔对流。该级别应称“简化运动学板块演化”，不能称完整地球动力学模拟。[S1-S5]

优先借鉴并评估接入 platec 的时间步核心，避免另造完整模拟器；但原版 Python API 无法直接注入用户指定的初始 Voronoi 分区、壳场和速度。若该要求保持不变，需要一个明确的上游扩展或受控适配分支，不能宣称安装 PyPlatec 即已满足。球面版本参考 tectonics.js，但不建议第一版移植其完整气候、岩石循环和浏览器运行时。[S1-S5]

## 原始来源比较

### platec / Mindwerks plate-tectonics

核实版本：`2a27c4fb137c657517bca62122b9de80e6b8c255`。

- `lithosphere.cpp` 初态由噪波高程和 `sea_level` 对应的阈值分出海壳与陆壳；随后从随机原点生长板块。它没有在所读初始分区代码中使用显式 Voronoi 求解，因此不应把该默认算法直接描述为用户要求的 Voronoi 初态。[S1]
- `update` 会移动板块，处理重叠；海壳按浮力/年龄规则俯冲，大陆碰撞分配折叠壳量，碰撞达到条件后发生大陆聚合；空白位置补充新海壳。存在循环重启和低活动终止规则。它确实有状态随离线步演化，且仍是为地形生成设计的简化模型。[S1-S2]
- `movement.cpp` 使用随机方向、速度、摩擦/碰撞脉冲与简化转向；源码注明部分公式为 hack。其步、速度和高程不能未经标定直接当成 Myr、cm/year、m。[S3]
- Python `create` 暴露 seed、宽高、海面比例、侵蚀周期、折叠率、聚合阈值、周期数和板块数；没有初始板块栅格/权重/地壳场/速度输入。严格 Voronoi 控制需要扩展。[S4]
- 平面地图坐标绕世界边缘回绕，适合周期矩形；不能把它说成球面板块模型。[S2]

适用判断：最短的可验证演化原型来源；其输出地形并不免除大陆自然度验收，默认噪波大陆初态也不是“从无大陆的物理成因模拟”。

### WorldEngine

`worldengine/plates.py` 的 `generate_plates_simulation` 调用 platec 的 create/step/get_heightmap/get_platesmap；完整 `world_gen` 随后移动大陆至图中心、加高程噪波、可选边缘海洋处理，再生成其余世界层。它是 platec 的世界生成流水线，不是另一套更高保真的独立板块求解器。[S5]

适用判断：参考外部算法适配与分阶段产物；本项目已有 TD/气候/水文路径，不宜为了板块基底整体接管 WorldEngine 的后处理。尤其 `center_land`、边缘修饰等操作必须连同板块层和坐标变换记录，不能只移动高程图。

### tectonics.js

核实版本：`e43927ce88e766b63e35e896f36bfb882a4c8de4`。

- `Plate.js` 维护壳、板块掩码及局部/全局旋转矩阵；位移由厚度、密度与均衡浮力关系导出；速度调用 `Tectonophysics.guess_plate_velocity`。这支持球面刚体移动的设计参考，不能凭函数名中的物理术语声称已解完整地幔动力学。[S6]
- `Lithosphere.js` 有 move、merge、rifting、subduction、accretion 和积分更新；壳年龄随步推进。张裂补充壳，俯冲脱离处提取保守材料作增生。其更新是时间演化，而不是一次性在边界画隆起。[S7]
- `CrustGenerator.js` 明确先按高度排序匹配设定的地球式高程分布，再从模板插值壳厚/岩性。初始大陆仍需种子与分布假设，不是单凭 Voronoi 自动产生大陆壳。[S8]

适用判断：最有用的是壳状态与板块几何分离、球面旋转和壳收支设计。源码存在 `Plate.move(megayears)` 参数名和上层传入 `seconds` 的命名差异，移植时应追踪具体换算，不能照名推断单位。[S6-S7]

### 学术出处与证据限制

platec README 指向作者 Lauri Viitanen 在 Metropolia 的学位论文 `URN:NBN:fi:amk-201204023993`。本轮访问论文入口遭站点访问验证，未取得全文，因此这里只将它列作原作者研究入口，具体算法结论均以上述已读取官方源码为依据，不声称复现论文，也不引用未核对的论文数值。[S9]

## 地壳、Voronoi 与速度的最小状态

以下为设计建议，不是既有能力。

1. 地域：先选一张有限、周期平面宏观地图作为独立实验来源，明确总尺寸、格距及边界。板块级尺度应覆盖大陆和海盆；500 km 是其中局部验收视窗，不必成为一个完整地球的模拟直径。初次分辨率可从 512² 开始，尺寸/板块数固定记录，成本和形态经原型再定。
2. 分区：使用确定性 Voronoi 种子；位置控制方位、密度影响板块大小。需可控面积时使用加权 Voronoi/power diagram，并校验空单元；权重不是角度，不能宣称普通 Voronoi 直接控制每块朝向。板块平移方向独立保存；需要转动则再保存角速度。
3. 壳：为每个格点或板块局部材料格保存大陆壳比例/类型、厚度、年龄和所属板块；可另有密度。大陆壳由少量连通胚胎在板块内部形成，可跨越初始板块边界，且不要求一板块一大陆；壳种子只是初态，最终轮廓必须随演化改变。
4. 边界：平面在共同坐标系下计算 `v_rel = v_B - v_A`，法向从 A 指向 B。`dot(v_rel,n)<0` 为汇聚，`>0` 为离散；切向分量描述走滑。球面应使用 `v(p)=omega×p` 在同一球面点求相对切向速度，不能对经纬坐标直接相减。
5. 时间：固定离线步数/时间索引，规定每步最大平移小于宏观格距的一定比例。若暂不标定物理时间，使用“离线步”，不标 Myr。更新顺序与冲突规则固定，不随采样/区块加载顺序变化。
6. 过程：大陆-大陆汇聚产生壳增厚/拼合；海-陆优先使较密海壳俯冲；海-海按年龄/密度规则选择俯冲侧；张裂处分开大陆材料并补海壳；走滑首版只移动材料，不凭空画高山。各过程至少导出迁移量、造壳、俯冲移除、增生与数值误差，不能仅有“大陆面积守恒”口号。
7. 高程：由演化壳厚/密度和简化均衡关系导出基础高程，再作明确的地貌尺度处理。海平面固定物理 datum=0；若水比例可控，用一次全域标定的高程偏置或水体积参数并记录结果，不在每个显示窗口重求分位数。

这里的“碰撞”是运动学材料规则；没有解应力、温度、黏弹塑性或地幔对流，山脉高度、俯冲角及真实构造速率均不具备预测效力。

## 有限域、球面与无限世界

| 方式 | 能保证什么 | 代价与限制 |
| --- | --- | --- |
| 有限周期平面 | 对应 platec 的最短接入路径；离线生成一次后可跨边界一致采样 | 拓扑是环面；平铺会重复大陆，不能称无限不重复世界 |
| 球面 | 无矩形边缘；刚体用 Euler 旋转；完整行星的板块相互作用明确 | 需球面邻接、重采样及地图投影；投影到 Minecraft 平面会有畸变/接缝，球体不会一一覆盖无限平面 |
| 有限开放平面 | 可取内部裁剪区作区域构造实验 | 必须规定流入/流出壳与速度，边缘人工性不能靠淡出海水掩盖；不能复用周期结果后声称开放边界 |
| 无限平面独特大陆 | 理论上可用固定绝对区域键、共享边界和足够依赖域预计算 | 时间演化会传递远处影响；邻区独立运行后拼图或固定窄 halo 不自动一致，需要另立可证明的依赖/分区设计 |

建议第一阶段明确为“有限固定宏观底图”；对游戏无限坐标入口另存映射策略 `periodic` 或 `outside_ocean`，如尚未决定则不启用无限模式。`outside_ocean` 可以支持无界坐标查询，但只有有限构造大陆，必须如此描述。现有 `LayoutSpec(mode=infinite)` 表示噪波式无界世界，不能悄悄把其语义改成周期板块图。

冻结底图解决的是“同坐标同结果、加载顺序无关、UI 与生产同源”，并不解决“无界且处处独特的真实板块历史”。后者应单列后续设计问题，不作为第一版默认承诺。

## 最小可行接入

1. 新增独立的板块基底产物：规范化参数记录、初始 Voronoi 种子/权重/速度、初始壳场、最终壳场/板块 ID/宏观高程、边界类型与速度诊断、固定过程采样历史和来源版本。保持旧噪波布局和星形大陆数据不可变。
2. 显式 CPU 准备入口完成演化与文件发布；产物整体 hash 绑定世界种子、各用途子种子、算法/求解器版本、初态、网格坐标、边界方式和演化步配置。读取接口只采样成品，不隐式推进模拟。
3. 独立只读采样器暴露 `elevation_m`、`ocean_mask` 及可选 plate/crust/boundary 层；按绝对 `(x,z)` 米制坐标采样，数组 `[z,x]`。周期/域外策略属于产物身份，插值和海岸判定规则也固定。
4. 新条件配置绑定上述内容身份，遵循 `make_conditioning_map` 工厂协议；`sample_raw` 的高程通道直接来自板块基底。气候沿用明确选定来源或标为占位，不因有板块就宣称生成了真实气候。
5. 单页 worker 从普通记录重建新配置并打开冻结数据，保留当前资源预算入口。现有代码硬编码重建 `LayoutSpec`，需要实际增加来源分支；不能只提供新闭包就声称已可用。
6. 宏观图像服务和前端以后读取同一采样器。主视图显示真实最终海陆与高程，板块线/速度是可切换覆盖层；返回地图边界、坐标、尺度、海平面、底图身份与图层。普通分区彩图不能作为大陆主图。
7. 最后才替换 500 km 验收链的来源选择与 `macro_fields` 消费端，分别记录板块宏观数据、TD 原始页和组合派生数据。任何 TD 条件依从/海岸修正保留独立证据。

## 分阶段验收标准

### A. CPU 机制与宏观地图

- 固定 `20261020` 重跑初态/终态内容 hash 一致；按相反查询顺序和重叠窗口采样一致。若库的浮点结果跨平台不保证逐位相同，生产以冻结产物身份为准，并声明重生成环境。
- 初态显示 Voronoi 板块与大陆壳两层；终态显示由壳演化导出的实际海陆。必须有初末轮廓/材料迁移对照，不能只比较山脉着色。
- 至少三组固定机制用例：大陆相向时增厚并产生拼合；海陆汇聚时海壳移除/增生账目出现；大陆张裂后两侧材料分开且空隙补海壳。记录过程，不要求地球级定量校准。
- 地图覆盖全域，并报告实际水比例、陆块连通分量及面积分布、海岸长度所用分辨率、板块面积分布和各边界长度。目标水比例不等于每个局部窗口水比例，阈值容差在实现规格中预先固定。
- 周期域的四边采样与插值一致；非周期域明确验收范围/边界条件。不得靠展示裁边隐藏不连续。
- 预览同像素坐标的海陆/高程等于只读采样器结果；地图身份等于 TD 条件配置所绑定身份。统计指标通过仍需人工检查大陆轮廓与构造格局。

### B. TD 条件接入

- 先验证 7,680 m 条件格上的坐标、列行顺序、负坐标和重叠采样，再按现有预算做一个明确选择的原生 30 m 单页。
- 保存实际条件高程、原始 TD 输出及必要的派生组合；分别测量粗海陆依从、海岸偏移和条件分辨率可表达的最小特征。不能要求粗条件保留细岛/湖，也不能把符号裁剪后的地图算作未经修改的 TD 海岸。
- 单页通过只能证明单页接入，不恢复或宣称完成 500 km 全域 TD、水文、侵蚀或 Minecraft 验收。

### C. 后续产品与全链路

宏观 UI 接到真实冻结底图之后，再由用户决定恢复哪一段 TD/河网/侵蚀验收。当前文档不改变相关任务完成状态。

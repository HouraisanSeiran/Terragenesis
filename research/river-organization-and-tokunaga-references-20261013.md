## PLRG 原文具体支持与拟借鉴

下表组织方向最初取自 [官方摘要](https://arxiv.org/abs/2610.00301v1)，本次以 [v1 正文](https://arxiv.org/html/2610.00301v1) §§3.4–3.8 核对。表中“拟参考”是工程推论，“采用程度”是本项目状态。

| 摘要明确描述 | 本项目拟参考 | 本次采用程度及未采用部分 |
| --- | --- | --- |
| 板块种子同时定义连续地形场和有限 Voronoi 类板块域，局部预处理直接使用几何域 | 先确定有界计算组织单位，再开展域内详细河网；把归属查询、依赖范围和重算范围明确化 | **设计组织参考，未实现论文式域生成**。本项目优先完整干流水系与汇水范围，不能把板块或存储块直接当流域 |
| 每个板块低分辨率采样，向海岸、局地低点或已有汇流点追踪 | 区分规划层、域内河网及精细几何，保留合法终点和失败状态 | **概念参考**。不采用板块内高地源点追踪作为当前生成算法；不把窗口边缘伪装成海岸 |
| 沿路径调整河流高度使存储段持续下降 | 持续下坡作为需检验的性质 | **本项目此前已有独立实现**，不是本次论文引入。当前连续剖面、实际三角面梯度与切深预算须用本项目证据验证 |
| 河网按板块惰性生成并缓存，各板块独立于邻居处理 | 有界按需准备、缓存身份和局部更新 | **设计意向，未验收域间独立调度**。现有 NPZ 保存与来源哈希不是论文式无限世界缓存/调度的证明 |
| 全分辨率查询精确计算到缓存河网的距离，并插值河高与本地地形混合；混合结果本身不缓存 | 可把粗规划与精细消费分开考虑 | **未采用**。当前保存实际床面网格并独立冷读，不以论文的按需混合替代实际床面产品 |
| 边界 warp 小于河流边界 margin，以此保证最终河槽下坡 | 边界与河槽要满足相容约束，不能只保证中心线段下降 | **已读原文前提，未采用其保证或参数**。保证限于其板块构造及河槽中心；外侧混合带另需更强裕量，本项目共享分水岭与跨域禁令需独立实现与验收 |

正文进一步明确了这些参考方向的适用边界：

| 官方正文及具体支持点 | 工程推论与采用程度 |
| --- | --- |
| [§1](https://arxiv.org/html/2610.00301v1#S1)、[§3.4](https://arxiv.org/html/2610.00301v1#S3.SS4)：板块是中间预处理域；几何域由邻种子平分面裁剪，不需要采样地形来寻找边界。点查询域受 warp 影响，与直边几何域不完全相同 | 可参考“域归属、几何边界、详细准备、消费查询”分离。将中间域换为水文规划域是本项目推论；任意 TD 地形没有论文配套生成的板块地形场，不能直接得到独立流域保证 |
| [§3.5](https://arxiv.org/html/2610.00301v1#S3.SS5)：局部低分辨率网格只留域内样点；规划高度对山地/高原衰减，且省略岛屿噪声。样点另存距边界距离，分别判定 border-safe、lake-safe | 粗规划与细节消费分层可参考，但论文规划高度并非原始地形的无改动采样。本项目已有固定原 TD、4m 切深预算，不能据本文引入规划衰减或替换真实来源 |
| [§3.6](https://arxiv.org/html/2610.00301v1#S3.SS6)：源点按高程降序；逐步选合法更低样点，不准交叉；海面、已有低节点、局部低点及步数预算分别结束。非 lake-safe 死端或只能进入边界带的路径整条拒绝，不截断到边界；正文明确河流不跨板块边界 | 可参考显式合法终点和拒绝状态。选择这些终点的物理有效性仍需本项目核实；这不是跨域干流协调方案，也不证明任意地形的边界一定是分水岭 |
| [§3.6](https://arxiv.org/html/2610.00301v1#S3.SS6)：按生成顺序将单路径原始高程仿射映射到源头/终点河高，支流终点接已定干流河高；完网后计算 Strahler 阶 | 说明论文把拓扑和河高一致性作为缓存产品。本项目既有共享床高/连续梯度实现独立于本文；Strahler 河阶也不等于 Tokunaga 侧枝统计，不能据此声称已核实指定 Tokunaga 论文 |
| [§3.7](https://arxiv.org/html/2610.00301v1#S3.SS7)、[§3.8](https://arxiv.org/html/2610.00301v1#S3.SS8)：缓存按板块整数标识惰性建立，存规划网格、节点、段和路径；查询逐一扫描本板块所有段，代价 `O(段数)`；最终高度按公式 (32) 即时混合且不缓存混合结果 | 可参考有界准备产品与只读消费职责。本项目继续保存实际床面网格；原文缓存不等于本项目现有 NPZ 已具备无限世界调度，也不直接支持全局段扫描的性能结论 |
| [§3.6](https://arxiv.org/html/2610.00301v1#S3.SS6)、[§4.2](https://arxiv.org/html/2610.00301v1#S4.SS2)：中心河槽归属要求边界裕量超过 warp 位移；整个谷地混合带留在本板块需裕量超过位移加混合宽度。作者配置中 92,800 个混合带样点有 6 个归邻板块，谷缘被裁剪；23,200 个中心样点均归本板块 | “中心线保持下降”与“整条谷地跨界相容”应分开验证。这是正文直接支持的验收分层，不把作者中心河槽保证转成当前实际三角面床底或谷缘的认证 |
| [§4.1–4.3](https://arxiv.org/html/2610.00301v1#S4)：作者只报告一组 seed 1 平面配置、10 个缓存、1,450 条段、222 条接受路径，最高 Strahler 阶为 2；16 个采样点/段未检出下游抬升。计时为 M4 Max、5 次冷启动中位数；球/立方体示例没有测量 | 可引用为作者对该配置的报告。本轮没有运行作者代码；这些结果不支持本项目多阶河网的 Tokunaga 拟合、流量真实性、水动力或全域性能 |

以上是原文支持与拟借鉴的对应关系，不是本项目自然度认证。论文的板块独立依赖“河流不跨板块”和专门构造的地形场；水文域归属、跨域干流及共享分水岭仍是本项目需要实现和验收的责任。

## Tokunaga 与历史引用的区别

[已有计划](../docs/td-fictional-world-natural-river-network-plan.md) 在“Tokunaga 侧枝统计”一段引用的是 **Zanardo 等，Are American rivers Tokunaga self-similar?，DOI 10.1029/2012JF002392**。这是另一个 DOI，不能用它替代用户本次指定的 `10.1360/zd2009-39-10-1413`，也不能把历史文档中的概括称为本次 2009 来源的原文结论。

用户已指定的用途是：将 Tokunaga 作为真实性拓扑评价，**不强制模板**。拟议评价可以记录冻结河阶定义、低阶支流汇入高阶河段的阶差频次、样本量及参考条件，但这些是工程待定义项，不是本次未读论文已验证的公式。是否自相似、拟合何种模型、适用何种网络及尺度，必须在实际读取该来源后明确。禁止为贴合统计目标而补造无汇水、逆坡或无水量来源的支流。

## 设计历史与 Nucleation 补充来源

历史计划中“先 TD 后逐河流域”“PLRG 仅借确定性”与当前 [CONTEXT.md](../CONTEXT.md) 的详细生成前冻结有限规划、共享边界和终点有所不同。保留其历史身份，本次不把旧计划重新提升为现行指令；用户最新要求为参考组织方式而不照搬板块模型。

用户另提出 Nucleation 用于当前灰度河网之后生成悬挑等特殊地貌，随后明确来源为 [Schem-at/Nucleation](https://github.com/Schem-at/Nucleation)。主协调已读取其官方 README 和 commit `51de345adce496c34e73a6458b2a2d107a1148c2` 的 `docs/features/sdf-and-fields.md`，将它识别为 Rust Minecraft schematic engine，包含 SDF 布尔/变换、Field3、体素化及 mesh/render 能力。该来源与历史计划中专指河道起始/支流萌生的 nucleation **不是同一含义**。本文件未独立读取该仓库，具体核实与采用状态以 [主交接记录](../docs/river-progress-and-reference-use-20261013.md) 为准；不把河源萌生文献误作悬挑生成依据，不把此补充来源标为已接入生产。

本轮仅补充来源与采用程度登记，没有新增生产算法。PLRG 已从摘要核实推进到官方 HTML 正文；指定中文 DOI 仍未取得书目或原文，Tokunaga 只读评价仍为待定义、待实施状态，不将检索失败或一般概念补成该来源的结论。

## 2026-10-14 实现状态补记

上述“本轮”保留为10月13日研究记录。后续有限水文规划及归属查询已实现，采用PLRG的程度仍为有界准备、只读查询和确定性组织的参考，没有移植板块模型或声称复现论文。现有成果与失败范围见[水文规划域记录](../docs/hydrological-planning-domain-progress.md)。

# 地表与地下首例的下一水力任务

本文件是实施边界，不是通过证书。当前工程已有连续地表片段、三维typed图和实际潜入/洞道/复出几何；旧地下扩散蓄量模型07/08/09未接受。几何通过不能自动提升水力、自然海口或整个流域状态。最新真实结果见[本轮交付](hybrid-river-delivery-20261006.md)。

当前接回状态仍为 refused：原生来源、材料账和7个区间占据查询已有独立证据，但sink带孔切片在旧端口消费器中拒绝。因此本文件中的水力接口尚不能消费新face包。

## 先修接口，而不是继续调积分器

旧连接使用两端Manning导通的较小值。近干接收单元会压低进水，即使两端已有较大水头差；精度或共同高程原点变化并未使完整双向事件通过。应基于最终实体的实际polygon、真实湿壁及沿程控制几何定义新模型，不把未知开口处理成零流量。

下面三项必须形成一个独立版本的模型契约：

| 接口 | 必须明确的内容 |
| --- | --- |
| 断面与连接 | 真实口域、湿壁、开放边、洞顶、整段控制槛及收缩；局部18个face只是局部断面，不证明全link无控制槛 |
| 唯一库存 | 19个cell及连接段的空间归属，真实几何体积与一维库容差；node和conduit不能重复计入同一段水量 |
| 本构与边界 | 动量/摩阻/局部损失、干湿处理、工程压力compliance、初始未标记水、供水及尾水；未知损失不自动等于零 |

可以显式定义理想工程粗糙度、无附加局部损失等假设，但必须标记为工程输入，不能命名为实测自然洞道参数。压力槽只影响数值库存，不扩大实际岩体开口；压力水头也不是洞顶以上的自由水面。

## 成熟引擎的适用性

已检查EPA SWMM固定revision及PySWMM主源码，摘要见`research/underground-hydraulics-engine-20261006.md`。其Dynamic Wave包含动量和双向工程边界，值得作为候选；本轮没有安装或运行它，也不宣称它无损支持本工程断面。

SWMM的CUSTOM宽度曲线不保证保留任意不对称、非凸断面的真实湿周；storage表和conduit均可能持有库存。仅匹配面积、不检查湿周和唯一体积归属，不能认为转换等价。标准报告期REAL4输出也不能替代逐内部步双精度配对账。

选择引擎前先完成一次保存数据转换可行性检查：逐断面对比床/顶高程、A(H)、P(H)、V(H)、压力库存和实际长度，并明确无法表示的断面。拒绝的接口保留拒绝，不用默认圆管或对称断面覆盖。

## 最小真实事件与完成条件

只在上述契约和几何门禁齐全后运行一个有界的新模型样例。两个物理事件仍为上游供水/退水与下游受控回水，各使用独立粗细时间设置；不重算已保存的地表全天水文。

- 保存完整物理时间、实际内部步、所有cell/link库存、正反向通量和三来源账；明确初始未标记库存。
- 配对地表扣量与地下加量，沿程累计Q不能在多个节点再次注入。
- 全历史水头1mm/体积1%与逐cell、来源、配对link绝对1e-4m³门禁保留；单一系统守恒百分比不能替代局部核账。
- 每case墙钟600s、200000 RHS、12000000 link评估、1GiB和64MiB文件预算保持；失败保存工作量和完整成品，不截取为通过。
- 独立冷读检查实际供水到复出及尾水返回地表，不以任意微量tracer到达代替稳定接收。

通过后才导出水量时序。连续三维水体网格、洪泛、自然海口、复杂多层洞道及独立跨域跨精度仍分别验收，不因一个工程样例通过而一并完成。

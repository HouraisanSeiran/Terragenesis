# 治理优先：分区派生流水线验收

日期：2026-09-28。用户要求先治理架构，再完成以下流程；本文件是验收范围，不是完成声明。

`扩散原始高度图 → 地貌分区与连续权重 → 各区独立处理 → 保存派生高度图/VDM → 导入游戏`

## 先治理

1. 来源、配方、尺度和模式能力有一份权威定义，界面、预检、构造器与存档配置共同校验。
2. 默认派生来源的采样接口只读取成品；缺失成品明确失败，不能从普通读取中启动模型。准备操作使用显式入口。
3. 同一区域/瓦片并发请求合并，重计算和等待不占用全局缓存锁；失败可报告和重试，关闭可结束待处理任务。
4. 工作区隔离编译、验证和正式打包；新版本使用独立文件名，不覆盖旧候选来冒充同一交付包。

## 再验收五个阶段

| 阶段 | 必须能检查的结果 |
| --- | --- |
| 原始高程 | 标记模型身份、种子、原点与单位；加工前后源数据摘要一致。 |
| 分区 | 平原、丘陵、高原、山地四类连续权重，值有限、范围合法、和为一；有明确的坡度/起伏依据。 |
| 独立处理 | 平原去除短尺度起伏，丘陵缓和局部噪声，高原保留高基面，山地保护脊峰；同一原始输入分别求候选，再连续融合，避免硬边界。 |
| 保存 | 原始与派生文件分开；派生高程及垂直 VDM 对应 `dy=派生-原始`，本阶段 `dx=dz=0`。版本、身份和校验和可核验。 |
| 游戏导入 | Minecraft 读取预先完成的数据；方块几何与派生字段对应、相邻区域一致、保存重载一致，海面仍为 Y62。 |

此阶段不加入地下河、洞穴拓扑、流水/风化侵蚀或新的悬崖算法。垂直 VDM 是本阶段的正确受限表示，不宣称已经输出洞穴或悬挑。

## 证据范围

先运行不改变参数的治理回归，再构建新版本。优先复用已保存的真实模型 NPZ，通过真实 Java 处理器生成区域成品，以独立 Minecraft 服务端验证导入。关停模型服务的离线读取必须成立。

真实样本没有海岸时，海面/岸线另用标注清楚的合成夹具；不得伪装为真实扩散海岸。有限样本之外不能靠重复、平铺或钳位充当模型输出。若为了服务端启动使用测试边界或限制生成范围，必须记录其范围及与普通世界的区别。

服务端验证可以证明方块写入、保存和重载，不代替客户端观感。按照用户既有要求，不直接操纵游戏界面。

## 剩余限制的记录方式

有限支持的平滑不等于大尺度平原整平。四类地形权重也不同于喀斯特、裂谷、石柱等地质群系标签。已有实验路径尚未全部迁入只读准备体系时，逐项说明，避免把默认流程的治理夸大为全部历史算法的治理。

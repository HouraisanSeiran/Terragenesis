# Terragenesis 前端与审查模块重构参考

- 文档版本：`2026-10-06`
- 适用范围：`web-preview/` 及其桥接、固定证据适配器
- 目标：在保持既有 API、公开 `window.*` 接口、DOM ID、分类和保存证据契约不变的前提下，逐步降低模块职责耦合，提高可读性和可验证性。

## 总原则

结构重构与算法调参分开进行。重构不得改变数值算法、固定来源、schema、身份校验、状态含义或公开 HTTP 路由。每次重构都应先记录受影响的公开接口，再运行对应回归；不能把“函数仍能运行”当作行为等价的充分证明。

原始来源不可变。前端显示、保存包适配器和显式预览都必须保留来源路径、哈希或 identity、坐标约定、单位、时间语义和能力边界。算法生成的高度场不得仅因训练材料来自实测 DEM 就标成“实测 DEM”。水面、床面、洞顶、压力水头和水深必须使用不同名称；水面显示要标明是原生积分、重构、抽稀还是未经认证的诊断结果。

用户确认的算法边界必须持续有效：AMR 是局部高精度对照，原生网格积分是水体积基准，uniform 保留为失败对照；内部物理秒步可以与外部保存帧抽样分离；自由出流为单向域外出流，内流盆地保留为湖泊；未知域外不继续追踪；断层和地下暗河在封闭实体、自交、体积、水力和地表连通尚未分别通过前，不得被界面或导出记录宣称为自然认证结果。

## 模块职责边界

### 前端协调层

`app.js` 只负责工作区导航、生命周期协调和公开门面。不要继续向其中加入新的数据格式解析、Three.js 几何构造或案例专用业务规则。

建议逐步拆出：

- `review-api.js`：HTTP/文件读取、响应错误和证据字节摘要。
- `review-selection.js`：不同案例的点选分派和选中记录格式化。
- `review-export.js`：审查记录组装和客户端下载。
- `review-time-controls.js`：时间轴、播放和保存状态切换。
- `workspace-*.js`：案例专用加载协调；只调用稳定的视图生命周期接口。

暂时保留 `window.surfaceReview`，把它当作兼容门面，不让新代码直接依赖 `app.js` 内部变量。

### 渲染层

`renderer.js` 负责共享二维画布、投影和兼容的普通案例绘制；不同数据模型应尽量独立：DEM、动态河网、静态 mesh、历史坐标和工程出口不要继续扩大同一个 `render()` 分支。Three.js 专用视图（保存表面、断层、地下暗河）应自己管理场景资源，但公开 `load / clear / render / resetCamera / reviewRecord / close` 生命周期保持一致。

渲染器不能决定算法认证状态，也不能从抽稀显示网格重新计算全域体积或流量。显示层只消费后端给出的语义和统计。

### 证据和契约层

schema、identity、坐标、单位、数组长度、三角拓扑和能力标志的验证应放在不依赖 DOM、canvas 或 Three.js 的模块中。这样可以单独测试，也能避免视图加载后才发现来源错误。

### 后端桥接层

`bridge.py` 保留统一 HTTP 响应和异常转换，但路由识别、静态资源白名单和领域适配逻辑应逐步拆出。领域模块负责业务校验和 payload，不应依赖 `BaseHTTPRequestHandler`。GET 只读接口不得隐式生成；生成必须是显式 POST，并有参数、时间、内存和响应预算。

### 固定数据导出层

`build_surface_review_data.py` 的发布流程、证据校验、序列化和各类案例构造应分离。增加新案例时优先新增独立适配函数或模块，不在 `main()` 中继续堆叠逻辑。固定来源哈希、原子 manifest 发布和“禁止生成”的回归必须保留。

## 编码规范

代码优先可读，不以减少行数为目标。JavaScript 和 Python 均遵循一行一条主要语句、正常缩进、控制流使用花括号、变量名表达含义和单位。避免多层三元表达式、连续逗号表达式、过长的单行字典和匿名长回调。

命名应区分：

- `timeSeconds`、`timeIndex`、`hourIndex`、`minecraftTick`；
- `bedElevationM`、`waterSurfaceElevationM`、`depthM`、`pressureHeadM`；
- `rockVolumeM3`、`sedimentSolidVolumeM3`、`poreWaterVolumeM3`；
- 原始坐标、局部坐标、世界坐标和游戏坐标。

注释解释“为什么”和语义边界，不重复代码本身。以下内容必须在接口或适配器附近说明：坐标轴顺序、单位、datum、时间含义、抽稀规则、水面来源、体积统计范围、未认证能力和失败状态。

## 推荐重构顺序

1. 先抽出不依赖界面的契约验证器，例如地下暗河、断层和保存帧 payload 校验。
2. 再抽出 `app.js` 的 API、点选、导出和时间控制；保留 `window.surfaceReview` 兼容接口。
3. 然后拆分 `bridge.py` 的路由与静态资源服务；不改 URL 和状态码语义。
4. 再按数据模型拆分 `renderer.js`，每次只迁移一种渲染分支。
5. 最后拆分 `build_surface_review_data.py` 的案例适配器和发布器。

每一步都应是小提交或小范围变更，避免同时解决架构、自然度、性能和水力语义问题。

## 验收清单

重构后至少核对：同种子结果一致；固定来源哈希和 identity 不变；非法输入仍在业务计算前拒绝；加载失败不留下旧几何、旧账本或可导出记录；工作区切换会丢弃过期请求；`window.surfaceReview` 及各专用视图门面仍可调用；保存帧时间和小时累计流量语义不变；二维抽稀不改变全域统计；断层仍是开放切面；地下暗河仍保持 `water=null` 和能力 false；浏览器加载的新增脚本已加入静态资源白名单。

本文件是后续智能体的重构参考，不代表所有目标已经实现，也不替代具体任务目录中的规格、测试和交付记录。

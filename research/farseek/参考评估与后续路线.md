# Farseek / Streams 河流参考与后续路线

核对提交：`delvr/Farseek-Mods` 的 `5bf5a8f7da8b7441d33f30a2e651d5d8407265bf`。仓库是多项目结构：Farseek 提供 Scala API，Streams 才是使用它生成河流与流动效果的 Mod。许可证为 MIT；若复制代码，须保留版权与许可声明。少量核对文件保存在 `source/`。

## 源码实际做法

- Streams 将区块划为 8×8 区块的 basin；主河道 basin 行每隔 4 个 basin 布置。主干分段 `Reach` 默认向西流，局部弯曲由 `bendsLeft` 和曲线控制；这是预定廊道，不是根据全球 DEM 求得的任意流域出口。 [basins.scala](https://github.com/delvr/Farseek-Mods/blob/5bf5a8f7da8b7441d33f30a2e651d5d8407265bf/src/streamsMain/scala/streams/world/gen/basins.scala) [Reach.scala](https://github.com/delvr/Farseek-Mods/blob/5bf5a8f7da8b7441d33f30a2e651d5d8407265bf/src/streamsMain/scala/streams/world/gen/segments/Reach.scala)
- `StreamsGenerator` 用噪声地表估算、海水泄出口检测和 basin 邻接关系，选择 `Mouth`、`Reach` 或 `TributaryBasin`；在访问相邻 basin 时按相同规则懒创建并缓存。 [StreamsGenerator.scala](https://github.com/delvr/Farseek-Mods/blob/5bf5a8f7da8b7441d33f30a2e651d5d8407265bf/src/streamsMain/scala/streams/world/gen/StreamsGenerator.scala)
- 支流在 basin 内用区块边缘最低地表候选出口、较高位置的泉源，以及四邻图的最短路径前驱连接。边权依赖相邻区块地表高度差；它规划的是有限 basin 内的路径，不是全域水沙模拟。 [TributaryBasin.scala](https://github.com/delvr/Farseek-Mods/blob/5bf5a8f7da8b7441d33f30a2e651d5d8407265bf/src/streamsMain/scala/streams/world/gen/segments/TributaryBasin.scala)
- 跨段连接用 `ChannelAtBorder` 保存边界河道截面、方向和各列底部高度。下游段读取上游出口并复制到入口，相邻截面再由二次或三次 Bézier 曲线连接；路径同时插值河床底和净空高度。 [ChannelAtBorder.scala](https://github.com/delvr/Farseek-Mods/blob/5bf5a8f7da8b7441d33f30a2e651d5d8407265bf/src/streamsMain/scala/streams/world/gen/segments/ChannelAtBorder.scala) [Segment.scala](https://github.com/delvr/Farseek-Mods/blob/5bf5a8f7da8b7441d33f30a2e651d5d8407265bf/src/streamsMain/scala/streams/world/gen/segments/Segment.scala)
- README 明确主干整段保持海平面、总体东西向且平行排列；为防噪声洞穴中的河流悬空，还在海平面附近加固体底层。这是无限世界生成的已知视觉限制，不应照搬为我们的全域河网。流动水流是游戏表现，源码证据不支持将其称作物理侵蚀或水沙守恒。 [README.md](https://github.com/delvr/Farseek-Mods/blob/5bf5a8f7da8b7441d33f30a2e651d5d8407265bf/README.md) [Streams README](https://github.com/delvr/Farseek-Mods/blob/5bf5a8f7da8b7441d33f30a2e651d5d8407265bf/src/streamsMain/README.md)

## 本项目的实施顺序

1. 本轮先完成 `raw diffusion → 连续地貌分区权重 → 派生 height/可选 VDM → 独立持久化 → Minecraft 导入`。原始模型缓存与派生缓存分开，记录种子、profile、参数、边界 halo 和版本；本轮实现仍在进行，不能把独立演示模块算作已集成。
2. 后续流水先求全域连续的流域图、每个连通流域的出口约束与跨区有向连接；允许内流流域，多汊河口留待后续。区域包保存入口/出口坐标、方向、流量和水面约束。可借鉴 Streams 的边界截面契约及确定性邻接，但不采用固定东西向海平面主干。
3. 再解河道水面纵剖面及地上、地下通道连接，要求上下游水面连续、非倒坡、非悬空。已有 VDM 仅移动曲面，能塑造崖壁与洞壁；穿孔、支洞、塌陷等新拓扑由体积密度/显式几何负责。
4. 在连续河网和几何基础上加入降雨—汇流—水沙通量台账，检验水量与泥沙守恒，再做侧蚀、搬运和沉积；游戏水流动画或噪声谷形不能替代此验证。
5. 风化先定义岩层耐蚀差异和局部松散物来源；风蚀另由风场、输沙、遮蔽和沉积决定。局部 VDM 可处理表面退缩，崩塌和贯通仍由体积拓扑处理。
6. 美化阶段再加入地形细节、河岸与崖脚沉积、植被和原版方块材质过渡，并以客户端观感、可玩性、跨区连续和性能验收。现有实验性崖壁/水沙模块是参考实现，尚未接入上述新流水线。

VDM 候选方法按用途分层：普通 heightmap 对应竖直位移，向量噪声用于坐标扰动，参数化岩壁/洞壁面片和 Voronoi 节理提供局部形态，侵蚀与法向退缩修改表面网格；需要新连通性的洞穴与崩塌使用体积密度/SDF，不由单值表面位移假装完成。

# TD 河网 M5 / M6 实现与验收

日期：2026-10-08。依据用户指定的 [Claude 实施建议（现已归档）](../deprecated-plans/Terraindiffusion河网算法完整实施建议.md) 中 Milestone 5 河床几何和 Milestone 6 泥沙与侵蚀。

本次完成 **M5 局部河床几何基线**和 **M6 有界、单向冻结水流泥沙回放基线**。单河段、转弯、Y 汇流、入湖、沉降、岩石侵蚀、失败前缀和真实 TD 局部河段均有保存后独立核验。未完成全域河槽构造、天然湖盆合并/回水及床变后的几何与水力反馈；不得据此升级为全流域自然河网或发布级产品。

## 实现与职责

| 模块 | 公开接口及职责 |
| --- | --- |
| `terrain_pipeline/surface_rivers/metric_channel_geometry.py` | `GeometryConfig`、`build_channel_geometry`、`validate_channel_geometry`、`save_channel_geometry`、`load_channel_geometry`；消费固定原床、选定 DAG 和显式宽深约束，构造共享细网格床面及断面，不求水流。 |
| `terrain_pipeline/surface_rivers/metric_sediment.py` | `MaterialParameters`、`SedimentConfig`、`SedimentDomain`、`SedimentForcing`、`solve_sediment`、`validate_sediment`、保存/加载；消费绑定几何和水流身份的区间回放，求固体迁移、侵蚀与沉积。 |
| `terrain_pipeline/surface_rivers/metric_bed_update.py` | `bed_from_inventory`、`bed_rejection`；材料库存到床高的 Exner 换算与提交前拒绝，不修改拓扑或重算水力。 |
| `tools/verify_td_river_geometry.py` / `tools/verify_td_river_sediment.py` | Main 所有的解析案例、真实来源适配、独立参考、细化、GLB/预览与证据发布入口。 |

M5 算法身份为 `original-bed-canonical-fan4-max-cut-v2`，存储 schema 为 `terragenesis-metric-channel-geometry-v1`。M6 分别为 `bounded-frozen-water-exner-v1` 和 `terragenesis-sediment-replay-v1`；算法身份和存储版本分开记录。

Main 负责接口、审查、集成与验收，两名实施代理分别负责几何和泥沙，最多三个活动智能体。没有修改旧求解器或 Claude 前端写集，没有启动服务、GPU、游戏或 Java 构建。

## M5 几何与审查修正

中心线只在固定原始 TerrainGrid 上搜索。源、终点、汇流点、显式锚点及入湖末段固定；度数为 2 的内部节点在原床高度与曲率目标下移动，默认最大偏移 6 m。完整河岸覆盖范围须留在有效源插值单元、同一 owner 与声明 corridor 内。宽度、深度是显式米制情景参数，边坡为水平/垂直 2:1，尚未标定为真实流域的宽深关系。

细网格使用统一索引，每个矩形的四角与中心组成四个三角形。每个顶点的切深取梯形断面包络的最大值，Y 汇流不把重叠切岩重复相加。端口取河段中点的真实横断面，在同一保存网格上以三角形与重心坐标采样，两侧半段共用一次端口记录。切岩体积是保存分片线性床面的精确积分，不宣称是未采样连续包络的精确体积；GLB 是床面显示导出，不是封闭岩体或水面。

审查后修正了以下风险，最终证据均使用修正后的 v2：

- 改造床面不再套用原床双线性插值的二次曲线证明。沿每段中心线，在全部细格线和 fan4 对角线处分段，逐个保存三角形证明床面下降；独立冷审另用三角形裁剪核验整段。
- 非局部切割重叠改为连续线段胶囊距离检查，避免仅查顶点而漏掉格点之间的狭窄重叠。
- 所有接触已知湿节点的原生插值单元及共享边界禁止切床。邻近切深按与湿单元的距离保守渐消，使用最小连续原床坡度的四分之一限幅。该策略保护已知湿支撑，不推断首鞍点以上的天然湖岸。
- 保存源完整范围、约束及其身份，修正体积积分基准；冷审使用固定外部 TD pin，核对 M6 指向的确切 M5 清单哈希。

## M6 模型、材料与独立参考

使用显式、未标定的均质材料情景。矩形水力半径 `R = width*h/(width+2*h)`，剪切 `tau = 1000*9.81*R*S`；无出流、干格或湖格的剪切为零。河道输运率为供给 `Q*mobile/water_volume` 与剪切容量的较小值；湖格平流并沉降，不在湖格侵蚀。沉降为 `settling_velocity/h * mobile`；侵蚀先消耗有限松散层，耗尽后才能侵蚀满足岩石阈值的有限岩石储量。

Exner 转换区分固体、含孔隙沉积和完整岩石：

```text
bed = initial_bed
    + (current_loose_solid - initial_loose_solid) / ((1-porosity)*area)
    - cumulative_rock_removed / area

initial_mobile + initial_loose + external_solid + rock_removed
    = final_mobile + final_loose + exported_solid
```

M5 切岩单独导出，不自动计为 M6 活动泥沙。每步同时保存节点收支、系统收支、剪切/容量和稳定性；非负供给、库存/岩底、receiver 坡度、冻结湿深与最大累计床变均在提交前检查。失败保存已提交前缀和独立可验证的下一候选拒绝原因，没有把拒绝步骤记入账本。

最终 [M6 清单](../verification/td-river-sediment/m6-20261008-03/acceptance.json) 状态为 `accepted_bounded_sediment_replay`，包含 10 份轨迹及一份新几何水流包。

| 独立参考 | 细步相对状态误差 | 验收 |
| --- | --- | --- |
| 静水沉降闭式指数解 / 独立 DOP853 | 0.0412141% | 没有静水侵蚀，固体转入床层，系统闭合。 |
| Y 输运至湖 / 独立 DOP853 | 0.0315143% | donor/receiver 成对输送、湖泊沉积与系统内存留闭合。 |
| 常量岩石侵蚀与指数冲刷闭式解 / 独立 DOP853 | 0.0536327% | 侵蚀岩石 0.0010272 m³，细步出口固体 0.0001392856 m³，岩石与固体分账。 |

三个参考均随时间细化改善，固定门槛为 0.5%。实际失败包分别保存零步拒绝和三步后拒绝：后者保存时间 `[0,0.5,1,1.5]` 秒，在请求的 30 秒事件中触发累计床变门槛，剩余时间未完成。

真实 TD 回放消费 M5 主测试段的实际保存床面，重新求 Manning 水流，绑定新的几何与水力哈希；没有沿用旧原床水流身份。端点控制长度为相邻段的一半，内部为两侧段各一半，总计 90 m，避免末段重复计面积。只输入选定源格的本地产流一次，域外 donor 明确排除。因此这是局部情景，不是整个上游流域事件。

900 秒事件采用宽 6 m、初始水深 0.01 m、初始松散层 2 mm、岩底位于初始床面下 0.3 m 的情景。泥沙步长 0.5 / 0.125 秒，细步 7200 步：

| 初始固体 | 0.702040000 m³ |
| 出口固体 | 0.00537462484 m³ |
| 最终存留固体 | 0.69666537516 m³ |
| 全局固体残差 | -1.9984e-15 m³ |
| 累计沉积固体 / 含孔隙体积 / 孔隙体积 | 0.0167356220 / 0.0257471108 / 0.0090114888 m³ |

真实事件没有露岩，岩石侵蚀能力由独立解析案例验证。累计沉积是过程中交换总量，不等于最终净床层增量。

任意非零床变设置 `needs_geometry_and_hydraulic_revalidation=true`。本算法在声明门槛内继续冻结原水流，只是单向形态近似；它不证明更新床面上的水流、断面和湖岸仍有效，也没有完成双向水沙反馈。

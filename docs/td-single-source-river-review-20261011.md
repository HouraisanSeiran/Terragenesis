# TD 河网同源逐层审查：本轮实现与未完成项

日期：2026-10-11。本轮目标按用户澄清为：让虚构世界的 TD 地形上生成的河流在外观与可测形态上接近现实，不要求重建某条真实河流或逐点吻合真实 DEM。视觉相似、参考统计接近、真实水量闭合是三个不同维度，均不能由单个维度代替。

## 已加入的审查入口

`terrain_pipeline/surface_rivers/metric_td_single_source_review.py` 从同一份已保存的 TD 水循环证据冷读地形、原床 D8 汇水图、单河段/湖泊以及保存的完整水量轨迹，核对来源 SHA256、父地形/图身份、河段床坡、有限域蓄排账。`tools/review_td_single_source_river.py` 默认指向既有 `rain-closed-30-evidence.npz` 与预冻结真实河道分布参考，命令示例：

```text
python -m tools.review_td_single_source_river --output verification/td-natural-river-stages/single-source-review-20261011/report.json
python -m unittest tests.test_metric_td_single_source_review
```

对应测试覆盖正常四层审查、重哈希修改原始高程拒绝和修改参考身份拒绝。入口不会调用动态水力求解。默认有限域只是 TD 16×16 格的 30 米局部窗口，以显式封闭边界模拟河段—单格湖泊：工程设置是可追踪的，不是天然海口。河段 5 米矩形横断面是模型假设，不是观测到的自然河槽。

## 与现实河网的差距如何报告

来源层：记录原始 TD 文件 SHA256、网格、有效面积、垂直基准和有限域边界解释；与真实 DEM 逐点高程差标为不可比较，因为不是同一地理流域。汇水层：记录原床图身份、终点类别、面积闭合和达 100000 m² 的候选河道支持；它仍是诊断路由，不是已挖出的可见河槽。几何层：检查保存的河段床高与坡度和原床一致，并给出原床候选的纵坡、曲率及相邻坡度变化；假定宽度、横断面和真实渠道不能冒充实测。水量层：核对强迫输入、河湖库存和对外输出，报告数值残差；缺少同尺度实测流量过程线和横断面，不能报告与现实河流的流量误差。

预冻结真实参考使用 90 米、48×48 格（4320 米）的真实空间块，当前保存水循环案例为 30 米、16×16 格（480 米）的有限域。若候选河道样本不足，参考差距标为不可评估；若足够，可列出纵坡/曲率/坡度跳变的 CDF 距离，但只能标为尺度不匹配的背景值，不参与通过率或自然认证。既有独立 TD 留出为 10/12 窗口、5/6 组通过；不能只选成功案例遮蔽失败组。

## 验证状态与下一步

新代码与测试已写入工作区，但本轮执行环境报 `VM_DISK_SPACE_INSUFFICIENT`，因此**没有运行测试、没有生成新报告，也没有新的数值验收结果**。既有阶段 0–5 文档中的数字是历史报告，不代表本轮复验。恢复运行环境后，应先运行上面两个命令并检查报告冷读身份和拒绝用例。之后选择原生 30 米范围内更大的 TD 局部域，以冻结的等尺度真实参考做留出统计；构建实际挖槽、连续岸线/横断面与水面可视化，加入同尺度专家盲评及失败案例，再判断是否达到“看起来像真实河流”。当前入口只建立可拒绝的同源复核，不是新的河网生成器，也不能证明视觉目标已实现。

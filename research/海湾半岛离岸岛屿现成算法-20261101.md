# 海湾、半岛、离岸岛屿：现成算法与复用位置

日期：2026-11-01。状态：一手源码与作者文档调研；仅写研究文档，没有修改地形代码、安装外部软件或模型、启动 GPU、运行地图生成。本文补充[海岸岛链生成与三角洲耦合](海岸岛链生成与三角洲耦合-20261101.md)，不重复其中 CEM、BRIE、Barrier3D 与 DeltaRCM 的过程模型评述。

## 直接结论

有现成实现可以借鉴，而且不必先做 D8 汇流。最直接的是 **Azgaar 的半岛/群岛模板与地形算子**，以及 **Red Blob mapgen2 的噪声海陆分类和海洋连通判定**。它们回答“怎样构造这种形状”；WorldEngine/platec 与 tectonics.js 更接近“大陆宏观基底从哪里来”。前述海岸过程模型回答“有地形、有水沙和波浪之后怎样演化”。这三类职责应接成流水线。[S1–S8]

建议本项目保留用户指定的方向：**板块基底 → 同源 TD 细化 → 连续近岸地形与海洋连通 → 水文/河网 → 河口三角洲与海岸沉积反馈**。半岛、海湾、基岩岛应先在基底与 TD 的连续地形中形成；水文无需承担所有海岸形状的初始化。沉积形成的沙嘴、屏障岛、口门坝则由后面的水沙过程处理。这是本项目的组合建议，不是已经复现的某篇算法。

## 两个最值得借鉴的具体机制

### 1. Red Blob：一个连续场，同时决定陆地、海湾和岛

作者部署的 `water.js` 可以直接读到以下逻辑：[S2]

```text
nx = (x - 500) / 500
ny = (y - 500) / 500
distance = max(abs(nx), abs(ny))
n = fbm_noise(noise, amplitudes, nx, ny)
n = lerp(n, 0.5, round)
water = n - (1 - inflate) * distance² < 0
```

这不是先画海岸，再随机向海里撒圆岛。各点来自同一个场，阈值会留下连着大陆的突出部分、伸入陆地的水域以及断开的陆块。参数决定形状统计特征，不保证每次都出现所有地貌类别，也不保证岛脊与大陆山脉的地质关联。

作者另一个教程明确给出“原始高程与 `1 - distance` 混合”的岛形方法，并建议只在低频层做约束、保留高频细节；同时明确噪声地形的真实性有限。[S3] 对本项目，值得复用的是**低频约束 + 连续细节 + 海平面阈值**这一结构，细节优先取现有同源 TD，而不是重新用 fBm 替换 TD。

随后 `assign_ocean_r` 从外海种子沿水单元邻接关系传播。与外海不连通的低地不会因“低于海平面”自动成为海洋。这里用的是多边形邻接图，没有要求规则栅格，更没有要求 D8 下坡方向。[S2]

注意：源代码的 `500`、归一化范围、外框全设水和 ghost seed 是其有限 1000 单位地图的具体约定。工程复用应换成板块/区域的明确外海锚点与世界坐标，不可逐页缩放套用，否则会制造页边海洋和重复岛形。

### 2. Azgaar：山脊、沟槽和海峡的可编排组合

当前模板源码显示：`archipelago` 含基础高度调整、平滑、垂直与水平 `Strait`；`peninsula` 以若干 `Range` 操作开始。生成器将这些工具分派到明确的高度算子，而不是仅提供一个不可解释的“自然度”参数。[S4][S5]

对本项目最可用的部分是这种**构造算子词汇**：连贯山脊/凸起能够延伸为岬与半岛，凹槽和低鞍可以留下海湾与海峡；相邻残余高地可能成为离岸岛。这一地形解释是基于高度阈值的工程推导，不能据模板名称断言其模拟了地质演变。

不建议照搬模板最终高程。板块层已给出大陆范围，TD 已给出局部地形，新的算子若需要使用，应是有幅度、有范围的近岸约束，并与原山脊/谷地相容。首先比较“只释放原有近岸海陆硬锁”的基线；只有不足时，再讨论是否引入可解释的山脊/沟槽组合。

## 形状算法与地貌成因的对应关系

| 目标 | 可直接使用的形状方法 | 若要声称有成因，需要另外什么 |
| --- | --- | --- |
| 一般海湾、岬角、半岛 | 连续高程场与海平面求交；低频范围约束；脊/槽组合 | 仅凭形状无法区分沉降、海侵、河谷、冰川、差异侵蚀 |
| 淹没山地形成的岩岛、溺谷湾岸 | 山脊和河谷连续伸入海底，低于海面部分连通外海 | 同源谷地结构、相对海面背景；若称溺谷，还应能指出被淹没河谷，不只是任意缺口 |
| 火山岛弧 | 板块层提供俯冲边界、方向与弧状基底，再用局部高程细化 | 构造/火山过程或显式构造初始条件；沿岸随机分布的小丘不构成该机制 |
| 沙嘴、屏障岛、河口坝 | 形状模板可用于实验初始条件 | 守恒泥沙库存、沿岸输沙、波浪、潮口和越浪反馈；参考已有 CEM/BRIE/Barrier3D 调研 |
| 峡湾 | 现成高度沟槽最多给形状相似案例 | 冰川侵蚀谷的深度、横断面、支谷与海侵背景；本轮未核实可直接复用的专用开源峡湾生成器 |

前述物理成因来源与学术模型详见已有海岸报告的 NPS/USGS、Ashton & Murray、BRIE 正式论文引用。本轮没有找到并核实一篇同时专门解决“海湾 + 半岛 + 离岸岩岛”且提供通用开源实现的学术算法，因此不编造一个“海岸岛链论文算法”名称。Génevaux 等 2013 是水文驱动地形生成参考，不能改称现成海湾岛屿算法。

## 对当前流水线的可执行建议

1. **板块研究负责宏观基底。** 在 WorldEngine/platec 与 tectonics.js 中比较所需输出，而不是把某个岛形模板升格为大陆来源；输出至少应能表示相对海平面的连续基底。板块字段是否包括边界、位移、抬升趋势由具体方法决定，不应先宣称候选都能提供。
2. **TD 负责同源细节。** 在既有海岸带内释放不必要的正负硬锁，让连续山脊、沟谷和低鞍决定湾、半岛与岩岛；约束带宽是本项目参数，不是 Red Blob 公式中的自然常数。
3. **先完成海洋连通，再把地形交给水文。** 几何与外海连通不依赖 D8。之后沿用工程现有不规则图河网，遵守用户已决定的 D8 退役范围，不因参考外部海岸代码重新引入旧路由。水文可以在长时演化中反过来改造地形，流水线不是禁止反馈。
4. **河口接现有三角洲/海岸账本。** 三角洲与可移动海岸沉积覆盖在基底之上；基岩岛对遮蔽、通道和边界的作用交给后续过程，不被沙质海岸平滑一并抹掉。形态改变后更新海陆与水路连通。
5. **复用优先级：概念与小算子，高于整套地图生成器。** Red Blob 的海洋连通最直接；Azgaar 的模板/算子适合明确的形状实验；WorldEngine 的分层顺序可作接口参考。当前用户暂停实现，因此此处不新增原型、验收图或运行计划。

上面五项是工程建议。没有做运行基准，不对自然度、耗时或“可以直接无缝接入”作结论。所有后续随机环节仍按项目固定 `world_seed=20261020` 派生用途子种子，来源与 TD 身份单独记录。

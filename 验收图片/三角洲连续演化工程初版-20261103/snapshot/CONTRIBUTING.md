# Terragenesis 维护约定

## 当前优先级

工程定位见 [README.md](README.md#工作区项目总览2026-10-21)：整个系统面向无限世界生成。新增算法同时评估局部形态、确定性、有界空间依赖、跨区与跨精度衔接，以及运行和存储成本。有限图幅用于验证；评估现成工具的可替代性时，以同等世界生成需求比较，不能仅凭其能制作有限地图就判定本系统没有必要。成熟内核仍优先复用，接入时验证其依赖范围和资源行为。

算法选型、开发与交付按根目录[无限世界地形生成评价标准](无限世界地形生成评价标准.md)逐项登记证据与未测项。

先保持可读、可验证的流水线，再增加算法。代码实现由用户指定的 GPT-6.1 Terra（medium）子代理分工完成，不再使用 Sol；主协调负责接口、任务发布、审查和验收。网页前端由用户另行指定的 Claude 实施，当前为 Sonnet，避免与其在途写集冲突。所有产物位于工作区；没有用户要求时，不操纵游戏界面。

原始模型数据不可变。加工结果另存，必须标记来源、坐标约定、算法版本和参数身份。实验原型不得自动接入默认世界；论文启发、论文复现和游戏验收是三个不同的完成状态。

## 模块边界

| 职责 | 边界 |
| --- | --- |
| 基础来源选择 | 负责构造基础来源和加工组合；不管理区块缓存或直接写方块。 |
| 区域准备 | 负责计算、依赖、文件校验与发布；最终应由显式调度入口触发。 |
| 只读查询 | 读取已完成数据；现有接口仍存在隐式生成，应视为待偿还技术债。 |
| 河网 | 不可变节点、河段和拓扑；与逐步水沙状态分开。 |
| 侵蚀 | 接收明确边界量和材料参数，输出几何变化及物质收支；不启动模型服务。 |
| 几何表示 | 高度图、VDM 和可改变拓扑的体积结构分别承担适用范围。 |
| Minecraft 适配 | 负责坐标映射、材料、水体及区块写入；不在单个区块内决定完整河网。 |

这些边界包含目标设计，不能据此宣称现有工程已全部符合。现状见 `research/长期维护与三维河网设计.md`。

## 编码规则

- 一个类只有一个主要职责。按实际职责拆分，不为减少行数制造无意义包装。
- 正常缩进，控制流使用花括号，一行一条语句。避免通配导入、全限定类名堆积和多层三元表达式。
- 名称表达意义与单位；只在小范围数学表达式中使用简短变量。配置参数及计算结果说明坐标系、单位和有效范围。
- 物理秒、离线迭代步和 Minecraft tick 不可混用；模型米制坐标与游戏方块坐标显式转换。
- 水面、床面、洞顶、压力水头分别命名。岩石体积、固体泥沙体积和含孔隙沉积体积分别记账。
- 非法输入、超界和非有限值尽早拒绝；失败不应留下部分更新的账本或成品文件。
- 算法身份变更与存储格式变更分别记录。开发阶段不要求旧测试世界迁移，实验版本保持明确隔离。

## 共用世界种子（用户更新，2026-11-03）

项目共用变量为 `WORLD_SEED = 20260903`，对应项目正式开始日期 2026-09-03；写入配置和产物元数据时字段名使用 `world_seed`。本节是当前种子约定的唯一权威定义，其他文档引用本节。后续新建正式世界、山体形态实验与连续测试统一使用此值，不因重跑而换种子。地形噪波、气候、降雨、光照相关噪波及其他随机过程使用由该世界种子确定性派生的固定子种子；不同用途分离子种子。

此前连续测试使用的 `20261020` 保留为历史基准。复验已有冻结地形、来源绑定及保存续算时，沿用产物实际记录的种子；新种子生成独立来源身份和输出目录。当前代码中仍有旧默认值和固定来源校验，本次文档更新不代表这些入口已完成迁移；新正式运行前须显式传入共用种子并核对最终记录，固定旧来源入口另行接线。

- 子种子由世界种子与稳定用途名确定性派生，记录派生方法及实际值；禁止用运行时间、系统熵或 Python 内置 `hash()` 作为种子来源。
- 空间采样依赖绝对世界坐标；时变过程依赖明确的物理模拟时间或固定时间索引，不依赖查询顺序、分块加载顺序或自适应求解步数。
- 光照的太阳位置等确定性物理量按明确时刻计算；云量等随机调制才使用固定种子，不以随机噪波代替太阳几何。
- 保存参数时记录世界种子、使用到的子种子和噪波参数。固定边界情景与噪波生成的驱动分别标注；尚未接入噪波的情景不得说成已由气候噪波生成。
- 需要多种子测试时显式列出固定种子集合，不随机挑选或因结果不好换种子。

## 变更与验收

2026-11-01 用户补充：面向跑团地图的交付允许采用游戏用途的近似精度。优先交付同源、主要河湖合理、跨区可衔接且成本可承受的地图；小幅高程差与次要支流问题可记录为遗留，不一律阻断。基础来源、坐标、有效数据和未知边界仍须明确。按风险运行必要检查，避免重复全域回放、层层防御框架或将科研级物理验证作为粗略DEM交付前提。粗世界DEM与局部90m/30m产品分别说明采样间距及适用范围；美学处理由用户另行安排。

用户验收图片默认采用[遥感式合成影像规范](docs/remote-sensing-acceptance.md)：可见地貌提供同源俯视主图，降水、温度和地下量等配定量专题图；记录来源、尺度、时间和情景。地形配色不冒充真实覆盖，季节对比不冒充长期气候变化；禁止用生成式图片补造结果。诊断面板、剖面与预算作为补充，历史图片不追溯改绘。

所有新验收图须在 Terrain Diffusion 生成地形基础上验证算法，逐图保存 TD 来源绑定；尽可能在同坐标、同地形身份和对应时间的同一张图中展示多个算法联合结果。独立合成网格或参考 DEM 不能替代 TD 验收，独立案例不拼成已耦合成果。

2026-11-03 用户明确启动独立于 TD 的山体算法开发：该后端的形态、连续性和性能验收使用实际保存的新算法来源，按真实来源类型绑定图片；TD作为可选对照。上述TD绑定要求继续约束既有TD算法链，不能用于阻止独立后端研发，也不能将新来源图写成TD耦合验收。

结构重构与算法调参分开进行。重构保持公开调用和已定义行为，并运行相关回归；算法变更另有样本对照、参数说明及结果记录。不要用一场大重写同时解决架构、自然度和性能。

测试以外部行为为准：同种子一致、跨区接缝、加载顺序、非法数据拒绝、流量/物质预算和导出余量。仅有函数能运行或账本守恒，不足以证明地形自然或水体在 Minecraft 中连通。

验证器使用固定入口和工作区输出目录。纯算法验证不启动 GPU 服务和游戏；检查通过后不重复运行无关大规模测试。完整构建与实验编译分离，避免无意覆盖已交付的 JAR。

## 后续偿债顺序

1. 拆开核心门面中的来源选择、缓存与采样职责，整理本次触及的密集代码。
2. 统一模式定义，消除 UI、codec、预检与构造分支的重复配置。
3. 拆开区域准备与只读接口，移出锁内重计算，设计明确的失败、取消与资源预算。
4. 统一数据格式说明和物理/游戏坐标契约。
5. 在上述边界下接入三维河网、多层局部侵蚀与体积导出。

# 山地河段守恒传播 v1

本次仅新增独立实验模块、聚焦测试、验证器与本文，不改变 task36 冻结文件、原始 TD 山地或 Sonnet 页面。固定输入为 `verification/mountain-rainfall/run-20261001T044308831149Z` 双山地六场景；每个场景的山地包与原生产流包同时绑定已接受 report 和 independent-review 的固定 SHA256。

## 接口与空间规格

`build_reaches` 接收完整原地形、D8 receiver、旧 flowline、人工出口、逐格 HRU 和面积；返回不可变意义的河段拓扑与空间归属数组。`route_local_discharge` 接收 64 HRU 的区间平均局地产流，不接收旧瞬时累积诊断。`save_routing_npz` 原子禁止覆写；`load_routing_npz` 必须提供从接受包读取的 `trusted_inputs` 和 `source_binding`。

分段采用最大连续单入流路径，支流源头、汇流处与终点为边界。汇流格归属下游段，出边长度归属其起点段，无重复边长。出口独立成段：普通山地最终29段（出口原已是边界），压力山地12段。每个陆地格唯一映射首次遇到的下游河格所属河段；出口本身也是合法首次目标。节点为无储水连接，所有储水在河段，初始全部为零。

原样本中心坐标为 `X=origin_x+col*30m`、`Z=origin_z+row*30m`，无半格平移。显示图像足迹边界扩展半格不改变线坐标。保留历史限高 conditioning、13格 halo、旧处理和海面减126m平移；没有新GPU推理、裁山或游戏尺度替代物理面积。

HRU h 分给段 r 的比例为 `格数(r,h)*900m²/area(h)`。所有列比例之和为1，保证全空间分配。每段局地输入为这些比例乘局地出流；上游输出只传递一次，绝不再注入累计 q。

## 传播与水账

示意固定速度为1m/s，不从填洼工作面构造坡度。长度为原 receiver 边的平面欧氏长度之和；驻留时间 `tau=max(length,30m)/speed`。终端无出边、原长度0m，使用明确的30m有效最小长度，因此驻留时间30s。该速度和长度下限未校准，不能解释为 Manning 或实测传播速度。

每步按合法上游到下游顺序传播体积。后向 Euler 线性库：`S_new=(S_old+V_local+V_up)/(1+dt/tau)`，`V_out=dt*S_new/tau`。所有量非负，`V_local+V_up=V_out+S_new-S_old`；内部传递在全局抵消。保存每段每区间局地、上游、输出、储量变化和残差，同时保存1345个储量状态与1344个出口平均 q。14天末剩余储水不丢弃，不强制清空。

完整输出14天1344步；450s敏感度为同一900s局地产流恒定拆成两半，共2688步，不重新生成雨量、土壤或快慢库。不称完整降雨模型收敛。报告记录峰值/峰时/峰衰减、体积重心、24/48/96/168/336h尾流、末储量与细步差异。正储水传播可以经过原人工填洼/逆坡规划，并不修复原床面。

## 静态验收与安全

静态加载不调用 `build_reaches`、准备入口、产流模型或时间推进器。直接校验已存 receiver 无环且 D8相邻、河线下游闭合、最大河段起终点/内部连续性、汇流归属、合法拓扑排列、首下游归属递推、原边长和面积计数；逐数组复算后向 Euler 方程与局部/全局水账。合法拓扑顺序不要求与组装队列顺序相同。

严格 NPZ schema/type、JSON键与非有限值检查，拒绝 object/pickle、额外/重复成员、非规范类型、畸形shape。加载在 `np.load` 前检查每个 NPY header 与推断的 T/N/R 和网格形状匹配。哈希绑定参数、源输入、全部结果，另要求外部可信输入：自洽重签的伪造不能靠自身哈希冒充接受源。

新独立预算：最多250000格、256 HRU、2048段、3000步、800万段时条目、3000万工作单位、768MiB未压缩字节。工作估算 `T*R*(N+1)+8*cells` 涵盖分配与静态图扫描；内存估算显式计入网格和多份段时数组。此次实际29/12段，两种步长均预检通过。没有静默复用旧200万工作上限。源维度/步数先检，再组装，实际段数得到后再检。输出不保存巨大逐时逐格水量矩阵。

发布写同目录临时文件、fsync 后 hard-link 到目标，存在目标或竞争者均不覆写；失败删除临时文件。验证输出采用全新运行目录。

# Claude 蓝图 M3 河道储量基线与河线路径审查

2026-10-08。Main 定义公开接口、派发两个实施任务、审查和独立验收；实施代理分别负责求解器和保存/采样。接口与固定门槛见 [.scratch 规格](../.scratch/td-river-blueprint/m3-interface.md)。

## 模型与适用边界

新增 `surface_rivers/metric_channel_state.py`、`metric_channel_solver.py`、`metric_channel_product.py`。不可变有向无环河网与时变状态分开，显式矩形断面采用完整湿周的 Manning 关系 `Q=A*(A/P)^(2/3)*sqrt(S)/n`。每个控制体有实际储量，显式有限体积更新同时使用上一步 donor 通量；Manning 特征速度与非负约束控制内部步长。forcing 间断限制求解步；输出采样发生在求解结束之后。

旧 conductance 求解器不具备 Manning 波速；moment/HLL 与 hybrid 原型需要更多二维、回水和端口几何条件，因此本阶段新建限定运动波基线。旧求解器、旧失败运行及其证据保持原样。

物理断面宽度与糙率来自显式未校准场景参数。活动输送要求正坡度，不添加假坡度穿越填洼平台。闭合/unknown 终端积水留存在本地储量中；超深、非有限状态、CFL、步数/trace预算失败只保留实际提交的前缀。冷读独立检查逐节点连续性、donor、Manning、CFL、边界预算，并核验下一步确实会按保存原因失败。

采样初态就是实际初态，后续状态按数值状态线性插值；区间平均 Q 按保存的数值步通量与输出区间重叠长度积分，瞬时末 Q 独立由末状态计算。这不改变前端 `state.time`、`signedEdgeQ`、点选与 `flowInterval()` 的既有约定；本阶段没有前端接入。

## 直线和直角的原因

证据：`verification/td-river-path-shape/td1024-20261008-01/path-shape-audit.json` 与 `angular-path-closeup.png`。对既有保存图做只读分析，没有平滑或更改河网。

边对统计每条入边及其receiver出边，在汇流处分别计入各支臂；这是全图统计，不只统计预览中较强的河线。

D8限制为八个栅格方向，D4限制为四个方向；预览直连格心，忠实显示这种方向量化。优先泛洪填平67,725格，所有这些填高格的出边均为零坡度。平台按BFS边数距离和格编号择路，缺少原床谷底方向约束，因此在图中产生公里级斜直线和成束平行线。原床D8仍有格点转角，不能把所有直线一概判为错误，但填洼平台的明显长直线不能认证为实际河床。

后续M4需要以盆地储量/溢流表示湖盆，M5需要按原床谷地构造连续中心线并验证曲率、汇流、分水岭与湖岸。单纯增加渲染样条可能越过山脊或错误湖口，不能作为算法修复。此要求已加入任务07。

# 无限世界地形生成评价标准

日期：2026-11-03。用途：全工程算法选型、开发和交付评价。用户已明确整个系统面向无限世界，在世界生成中部分替代 World Machine / Gaea；有限地图效果与单个算子的速度只是评价的一部分。

## 共同前提

- 世界坐标域可以持续扩展；每次准备操作处理明确、有限的范围。无限世界不要求同时存放或计算无限数据。
- 地形、山体、河湖、环境和局部三维几何服从同一世界组织。有限窗口是开发与交付单元，窗口验收不自动等于无限系统验收。
- 地理坐标使用米、海面基准与有效范围明确。种子统一引用 [CONTRIBUTING.md](CONTRIBUTING.md#共用世界种子用户更新2026-11-03) 中的共用 `WORLD_SEED`，各用途确定性派生；历史来源保留实际种子。
- 质量、控制能力和资源开销共同评价。允许为游戏世界采用有依据的近似，分别说明几何构造、等效过程和物理演算。
- 成熟方法优先复用。评估替代工具时采用相同范围、精度、依赖、增量生成和交付需求；不把有限图幅制作能力等同于无限生成能力。

## 评价项目与证据

| 编号 | 标准 | 最少证据 | 常见未通过情形 |
| --- | --- | --- | --- |
| E1 | 按需生成与有限依赖 | 给出点、窗口、山体或流域所需的空间邻域、层级和工作上界；远处同大小请求仍按同一规则计算 | 递归追踪不断扩大；将全域数据切文件后仍需全域求解 |
| E2 | 确定性与查询顺序无关 | 同种子复跑、乱序点查询、不同分块大小和负坐标比较；登记运行环境与误差 | 依赖加载顺序、窗口归一化、系统熵或隐式全局状态 |
| E3 | 跨区连续与共享结构 | 重叠值、分块边缘高度及坡向；山脊、岩层、谷地和水体跨边界保持一致 | 高度能拼接但坡向断裂；重复边框；边界成为假分水岭 |
| E4 | 多尺度一致与细化 | 固定世界位置的粗细公共采样点、粗细形态和细化接口比较；写明采样与滤波语义 | 改变格距就移动主峰、改换河道；上采样冒称增加几何细节 |
| E5 | 有辨识度的山体形态 | 关闭高频沟壑与材质，检查多视角轮廓、体量、峰壁谷组合、剖面和区域过渡 | 各类型只是同一锥体改高度或沟壑密度；平面有纹理而山体同形 |
| E6 | 水文与地貌相容 | 最终几何上的汇水、主要河湖、分水岭及终点；保存地形修正幅值和影响范围 | 把沟壑掩码当真实河网；任意窗口边当海口；沿用改床前失效拓扑 |
| E7 | 可控编辑与有限重算 | 改变一项控制后，记录几何变化、依赖传播和需要重验的边界 | 局部编辑隐式改变远处地形或吞并更多流域 |
| E8 | 计算、内存与存储可承受 | 固定机器与配置，分别记录点数、格距、覆盖范围、过程步数、冷/热缓存时间、峰值内存、缓存/成品大小 | 用渲染帧率代表生成成本；忽略准备和IO；通过更换精度掩盖成本 |
| E9 | 可保存、可追溯、可消费 | 原始/派生关系、来源类型、算法版本、参数、子种子、单位、坐标、数组摘要、冷读及消费者证据 | 仅有截图或内存结果；伪造TD身份；成品缺来源或无法重载 |

E4须区分两种合法语义：直接采样同一固定几何时，公共点应一致；采用明确的低通或LOD近似时，记录滤波尺度、误差与过渡，不能声称公共点严格相同。物理地形身份不随展示LOD偷偷改变。

## 性能如何比较

1. 固定格距，增加窗口点数，测吞吐及内存增长；固定范围，提高分辨率，测新增样本与过程成本。
2. 固定请求规模，在不同世界坐标和不同历史缓存量下测试，确认局部生成不隐式扫描已生成的整个世界。
3. 分别测基础场、形态塑形、细节、河湖、保存与加载；渲染单独计时。注明计时是否包含初始化。
4. 缓存有明确容量、命中/淘汰与重算语义；不能用持续增长的隐藏缓存换取虚假的固定请求成本。
5. 扩展性结论同时需要算法依赖分析与测量。少数大坐标样例不能证明数学意义的无限范围；总成本至少随实际交付样本数增长。

首轮独立山体开发采用有限CPU预算：常规验收每窗口最多512×512采样点，目标基础生成每窗口不超过30秒、进程RSS不超过2 GiB。它们是本轮待测工程目标，不是既有成绩或未来所有分辨率的承诺；完整制图另记时间。超预算保留失败与当前配置，先定位热点，不改种子或静默降采样。

## 交付状态

| 状态 | 可以声称什么 |
| --- | --- |
| 方法/接口完成 | 有算法说明、明确输入输出和必要测试，尚无足够视觉/规模证据 |
| 有限域候选通过 | 指定范围的几何、来源、连续性与资源检查通过；形态仍需实图审查 |
| 无限生成性质得到支持 | 有明确依赖上界、跨区域/跨精度和增量证据，注明支持的坐标、尺度与过程范围 |
| 生产后端可用 | 真实准备、保存、冷读、消费者和失败处理已闭合，资源达到目标 |

各项目独立登记“通过/未通过/未测/不适用”及证据路径，不用测试数量或模块数量折算成熟度。E5需要实际形态审查；E6未接入时保留未测，不能阻断纯山体算法研发，也不能被其它检查代替。

## 当前独立山体研发

实施入口：[山体形态规格](.scratch/mountain-morphology/spec.md)。第一轮验证无需TD的山体来源、三种结构差异及混合场、可关闭的方向性沟壑、世界坐标一致性与实际成本。后续再推进结构丰富度、局部三维、宏观来源与河湖接线。

新独立来源的图片按其真实算法和产物绑定；TD仅作可选独立对照，不要求为新算法启动模型。俯视地形配色图、多视角无材质几何、关闭细节对照及剖面共同呈现，沿用 [图片规范](docs/remote-sensing-acceptance.md) 的尺度、来源与诚实标注要求。

# 长期维护与三维河网设计（2026-09-28）

## 审查结论

现有项目有可继续演进的边界：`BaseTerrainSource` 供区块采样，`region.processing` 不修改原始格网，`.rmraw` 与 `.rmd` 各自校验身份和内容，`TerrainBiomeSource` 复用同一地形采样。它还不是可直接承载全域三维河网的统一数据平台。尤其要先消除配置契约重复、单位歧义和区域生成期间的隐式状态，再把独立原型接到默认预设。类短或能通过当前测试本身并不能证明长期可维护。

## 论文可借鉴范围

已阅读 Nilles、Günther、Wagner、Müller，*3D Real-Time Hydraulic Erosion Simulation using Multi-Layered Heightmaps*，VMV 2024，DOI 10.2312/vmv.20241211，全文见 `research/sources/vmv20241211.pdf`。论文的每个水平格最多存多个垂直柱；每柱分岩床、砂、水和顶板，用相邻柱虚拟管道转运水与悬沙，砂按休止角滑移。侧向侵蚀先累计损伤，达到阈值时分裂岩柱形成悬挑；承载传播再坍塌薄弱或悬浮结构。其 CUDA 样例使用最多 8 层、84 字节/柱；报告的 RTX 3070 时间是特定场景的每模拟步性能，不能推断本项目 Java 区块生成速度。

论文解决局部多层高度场的侵蚀与拓扑，不负责生成全域河网、跨区域长期水文或洞穴连通；洞穴样例预先切出了引导洞穴。其开放边界把物质移出场景，封闭边界用蒸发避免溢出。我们可先借鉴水/沙/岩分账、有限出流、侧蚀损伤与承载检查，不能只复制渲染形状宣称复现物理。完整多层柱、虚拟管道和 GPU 预算属于后期局部实验，不应放进本轮默认生成。

## 渐进河网路线

1. 独立建立不可变 `RiverNode`/`Reach` 图：节点有世界 `x,y,z`、水头、流量、泥沙与类型；边有上游/下游、截面和 `Surface`、`OpenUnderground` 等通道模式，湖泊用有库容曲线和明确出口的节点。先按分水岭和出口定向为无环图；除显式湖泊/瀑布边界外，下游水头不得上升。支流汇合使用同一个节点与同一水位，出流量为入流量及本地径流之和，再按有界 `width ~ sqrt(Q)` 生长宽度。这是形态先验，不是水力学证明。
2. 从中心线扫描可变截面的管状影响域，用平滑 mask 限制处理范围；只更新与水体连通、在水面以下受浸润的床岸表面。区分路径切向、实际速度方向和岩壁法向，避免将整根管柱下半部都当作受蚀地下实体。先用高度场一维 stream-power/二维浅水验证水位和截面，再加曲面薄层流；地下明渠与满管有压流分别建模。
3. 把侵蚀写成受材质、湿润度与剪应力约束的 `E = M K max(tau - tau_c, 0)^p` 候选律，并记录每段水、悬沙、床载、侵蚀、沉积与边界出入。浮点体积先累积，达到体素阈值再发放 Minecraft 方块，残差留在台账中，不能每步取整丢失泥沙。湖泊若无出口，入流必须增加库容/水位或经过显式蒸发、渗漏；不能在稳态图中充当无限汇。
4. 局部 VDM 更新既有河床/河岸表面；穿孔、独立岩块、塌陷和多层柱属于体积拓扑阶段。跨区先交换图节点、出流和泥沙边界状态，再发布区域 artifact，最后验证不同准备顺序和读盘重建逐值一致。独立原型通过后再考虑默认世界接入，现有调参原始与区域派生模式保持可用。

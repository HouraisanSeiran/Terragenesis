## 2. 建议在当前实现中优先核对的事项

### 2.1 明确坐标转换及世界边界

建议在现有适配层就近记录：源坐标系、显示坐标系、转换方法、适用范围、距离与面积计算方式，以及边界是否连接。无需为此另建一套框架。

Terragenesis 当前采用 X 向东、Z 向南的米制平面；civ-atlas 使用球面及经纬度主图。把方形 DEM 拉伸成 2:1 图像只能改变显示布局，不能建立正确的球面距离、极点和邻接关系。

- 若当前路线是有限区域接入：保留米制坐标作为地形查询依据，明确地图位置与源坐标的映射；超出覆盖范围返回未知或越界。
- 若当前路线已确定完整球面换源：沿用该决定，核对重采样、东西接缝、南北极与源覆盖策略；源的南北周期连接不能直接当成球面极区邻接。
- 若经纬度只是显示用的示意映射：在元数据中声明，旅行距离和面积使用选定的实际度量。

原交接已指出板块 origin 表示格网边界，TD origin 表示原生样点索引。两个 reader 各自按元数据转换；建议用首样点、相邻样点和边界点检查半格偏移。

完成判断：同一地点能在源数据、取样结果及地图点选之间对应；世界边界的行为与已选路线一致。

### 2.2 保留高程、水体分类和有效性的独立含义

建议给外部地形使用明确的来源类型及版本，在现有导入体系中增加适配即可。交换内容优先采用浮点高程、有效/未知掩膜、海洋分类和完整格网元数据；PNG 可继续承担预览。

现有 civ-atlas 高度图协议把海陆分类编码在海平面灰度两侧。将 Terragenesis 产品直接套入该协议，会损失负高程陆地语义，也难以表达未知区。分类依据应来自对应产品，不能统一用 `height < 0` 判海。

另需分开床面高程与湖面高程：Terragenesis fixture 的 `bed_m` 是床面；civ-atlas 的 World 有独立 `waterLevel`，Raster 中湖泊像素可表达水面。建议明确查询返回的是哪一项，避免把湖底直接用于地图水面。

完成判断：负高程陆地保持陆地，未知区保持未知；湖底与湖面字段含义明确，重新加载后来源身份一致。

### 2.3 核对栅格化是否再次改变地形

建议外部源模式明确每一步的处理权限：

| 处理 | 建议 |
| --- | --- |
| 配色、符号、文字、纯显示纹理 | 复用适用的现有渲染能力 |
| 改变 elevation 的噪声、平滑、岸线位移、河谷刻蚀 | 按当前路线显式关闭、受约束执行，或保存为独立派生产品 |
| 点选、高程查询、海陆判断 | 明确读取原始源还是派生源，与地图实际用途保持一致 |

`raster.ts` 的 `gully` 字段注释说明其用于明暗，不改变 elevation；其余噪声与刻谷可能直接改变栅格高程，应逐项区分。不能仅凭关闭一个细节开关就认定整条链已经保持源地形。

备份交接曾记录“陆地城址被绘制成海面”的问题及修复。换源后建议复用这类城址检查，额外观察低地、湖岸及跨页主河；无需重复全世界几何审计。

完成判断：地图海陆与查询分类一致；原始高程和允许的派生高程能追溯，放大或切换绘制入口不会无声明地换源。

### 2.4 区分显示接入与文明数据接入的完成范围

建议按当前任务的目标验收：

- 目标若是地图显示与只读查询，先完成该闭环，气候与文明扩展可继续独立推进。
- 目标若包含文明推演，则核对地块邻接、城镇选址、道路、湖泊和主河是否基于换源后的世界；沿用旧地形的结果需要明确适用性或重建。

civ-atlas 的 `World.flux` 注释单位约为“地块 × 米/年”，不能直接用 m³/s 数值替换。建议为所有实际接入的水文量声明单位与转换；只显示河线时可先消费几何与稳定 ID。

气候和群系可采用当前已选来源或另行计算，但须记录各自来源。现有 native-event 的两个 15 天声明事件不能直接作为年降水或长期气候。跨源组合可以交付游戏近似结果，说明组合规则即可。

完成判断：交付说明明确覆盖显示、查询、生成或文明推演中的哪些部分；每个实际使用的字段有可解释的来源与单位。

### 2.5 继续采用分级分辨率与按需准备

原交接的 5 km 世界 DEM、必要时 2 km、局部按需 90 m/30 m 路线仍可作为起点。是否增加 250–500 m 中间层，由当前显示或玩法需求决定。

建议保留河流中心线、湖泊边界、出口与稳定 ID，使窄于粗像元的主河仍能显示，也能约束局部细域。DEM 插值和放大图片均不能增加真实地形细节。

固定 owner 页、独立缓存与显式 prepare 沿用当前实现。缓存身份建议覆盖来源身份、生成/加工参数、页坐标、分辨率及算法版本；只读查询消费已发布产品，缺页返回未准备。固定种子本身不足以保证不同 TD 请求尺寸生成的重叠区域一致。

完成判断：重复请求复用同一冻结页；局部读取顺序不改变结果；细域主河、湖面和出口继承已发布的粗约束。

## 3. 建议的最小验收样例

在现有测试或诊断入口补充缺项即可。优先选择一处跨 owner 页、包含主河或湖口的冻结区域。

| 检查 | 可观察的通过条件 |
| --- | --- |
| 坐标 | 首样点、内部点、页边界点在源与地图上对应，没有轴向颠倒或半格偏移 |
| 分类 | 已知海洋、负高程陆地、内陆水体和未知区分别按来源表达 |
| 接缝 | 跨页主河及湖口没有明显断裂；小幅高差可记录为遗留 |
| 绘制一致性 | 作者图、玩家图及点选查询采用已声明的同一地形来源或派生关系 |
| 可复用性 | 重开冻结产品、改变读取顺序后，身份及查询结果保持一致 |
| 按需准备 | 缺页状态可识别；同页重复请求复用；中断后不把半成品当 ready |

如当前样本没有某类地貌，可用小型数据夹具验证分类和坐标逻辑；最终地貌展示仍按原交接使用 TD 来源。结果记录实际范围、格距、来源身份和必要资源开销。游戏用途允许小幅高差与次要支流差异，无需以科研级全球验证作为此次换源交付前提。
